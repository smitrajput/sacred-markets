# Checkpoint 02: DemoPriceGuard and TradeEngine (core engine)

Contracts and tests only. Nothing deployed, no transaction sent, no frontend change. `MarginVault` and `V4SpotVenue` are unchanged (no integration fix was needed). Green tests are evidence, not a production safety claim.

## What was built

- `contracts/src/DemoPriceGuard.sol` (runtime 937 bytes). Testnet operator fixture, not an oracle. Immutable separate `priceAdmin` and `maxAge` (constructor allows 1 s to 1 day; deployment value 86,400). `update(price, timestamp)` is admin-only; price domain 1e6 to 1e13 micro-USDC per whole BTC (documented: with `Math.mulDiv` nothing in the engine can overflow in that range); future timestamps and timestamps earlier than the stored one are rejected. `read()` returns price, timestamp and `fresh` (price exists and age <= maxAge). Pool spot is never consulted and no keeper can update it.
- `contracts/src/libraries/EngineMath.sol`. Policy constants and all arithmetic through `Math.mulDiv`: markup, atoms, value, sale floor, rebalance quantity.
- `contracts/src/TradeEngine.sol` (runtime 14,756 bytes, EIP-170 limit 24,576; initcode 16,383 of 49,152).
- `contracts/src/interfaces/IDemoPriceGuard.sol`.
- `scripts/push-price.ts` (and `bun run price:push`). Explicit operator refresh: requires `--guard` and `--price`, defaults to a dry run, only signs with `--broadcast`, checks chain 5042002, guard code and that the signer is the guard's `priceAdmin`, simulates, reads back the receipt. It was type-checked and linted but **not run** (no guard exists yet, no broadcast now).

## Engine behaviour (as implemented)

Immutable policy: E = P, C = 2P, term 1,209,600 s, annual markup 1,000 bps fixed at open `M = floor(P*1000*1209600/(10000*31536000))`, LP share 7,700 bps (split done once, inside the vault, on collected markup), trigger 16,000, restore 19,000, initial coverage 19,000, friction configured 300 (constructor, hard cap 460), dust 10,000, max live 32. A `termsHash` binds chain id, engine address, vault, venue, guard and the policy values; `open` rejects any other hash. No upgrade, rescue or admin withdrawal; debt and ownership are not transferable; every state-changing function is `nonReentrant`; token moves use `SafeERC20` with exact balance-delta checks.

- **open(E, userMinBtc, deadline, termsHash)**, trader = `msg.sender`. Validates terms, deadline, dust, wiring (vault and venue both bound to this engine) and a fresh price. `minBtc = max(userMinBtc, floor(floor(C*1e8/price)*(10000-f)/10000))`, must be positive. Then, atomically: `vault.reserveOpen` sends the full 2P from recorded depositor cash; the engine buys through the fixed venue (exact approval, actual balance increase must equal the reported output and meet the minimum, input fully spent); coverage must be at least 190%; the position is recorded and `AssetAcquired`, `DisclosedSaleAgreed`, `Pledged` are emitted; E is then pulled from the trader and `vault.confirmOpen` collects it; finally `Opened` is emitted. The complete sequence is atomic. No public reservation or confirmation exists outside `open`.
- **repay / repayAndRelease**: anyone, paid from `msg.sender` only; overpayment reverts; principal first (`repayPrincipal`) then markup (`recordCollectedMarkup`), so the vault, not the engine, does the cumulative 77/23 split (the engine mirrors the floor in `lpAllocation` for display). Partial repayment keeps all collateral. At zero debt the vault position is finalized once and all remaining BTC goes to the original trader. No oracle read; works while funding is paused and prices are stale. P = 0 with markup owed stays live in the vault.
- **ownerClose / settleMatured**: recorded trader only / anyone at or after maturity. Fresh price required. Sells all collateral with `minOut = max(caller, independent floor)`; proceeds go to principal, then markup, any surplus to the trader; a principal shortfall is booked with `vault.settleFinalLoss` after the recovered amount was repaid, remaining markup is written off, collateral and debt zero, vault finalized once, `Closed` emitted with gross loss and written-off markup.
- **rebalance(id, minUsdc, deadline)**, permissionless, the engine picks the quantity. Eligible only when `V*10000 <= D*16000` (healthy positions revert before any subtraction). `g = ceil((R*D - B*V)*B / (R*(B-f) - B*B))`, `sellAtoms = ceil(g*1e8/price)`. Partial only if `g < V`, the input is less than all collateral, the independent floor is positive and the worst-case remaining principal is at least dust; otherwise full close. Actual proceeds are applied principal first then markup; strict >= 190% is checked against the one captured reference, with a documented tolerance of one BTC atom of reference value plus one USDC atom, reported in the `Rebalanced` event (`toleranceUsed`). **Documented exception:** if the actual partial proceeds would leave 0 <= P < dust with debt owed, the engine sells the remaining collateral in the same transaction under the same reference and completes the full close (second-leg failure reverts everything); if the partial proceeds clear all debt, the remaining BTC is returned unsold and any surplus goes to the trader. There is no keeper reward and no force-close function.
- **positionValue(id)**: `floor(floor(collateral*price/1e8)*(10000-f)/10000)` and freshness; never reverts on stale or missing price (returns not fresh, so the vault scan fails closed). P = 0 positions still report freshness.
- Views for UI and keeper: `quoteOpen`, `quoteRebalance`, `getPosition`, `activeIds`, `debtOf`, `coverageBps`, `policyTermsHash`, `isWired`.

Fork cases (real pool, real USDC and cirBTC, real adapter, fork-only balance setup): open, third-party full repayment and release; and an engine-chosen partial rebalance after the reference falls to 80,000 (sale executes above the oracle floor, remaining principal at least dust, coverage back above 190%). Note for fork authors: Arc rejects draining a nonce-0 account to exactly zero ("Cannot clear balance of empty account"), so fork funding keeps one extra atom.

## Limitations and open items

- Prices come from an operator fixture; a stale or wrong operator price blocks or mis-sizes opens and sales (repayment and release never depend on it). Liquidity and venue slippage beyond the friction budget revert the whole operation rather than degrade.
- CORRECTION (see `02-boundaries.md`): the `InitialCoverage` revert IS reachable. At small equities, BTC atom rounding alone (even at zero execution cost) can leave initial coverage under 190%, so some valid-looking opens are rejected and rolled back. The earlier claim that it was unreachable was wrong. The frontend quote must check initial coverage against the actual DEX output, not only the oracle minimum.
- Not tested (at the time of this checkpoint): explicit reentrancy attempts (guards are `nonReentrant` and the venue is the only external swap path); LP-side share conservation inside the engine driver (covered by the vault suites); a handler-invariant campaign for the engine (a bounded random driver was used instead); mutation testing.
- The fork cases ran on the pinned block only; no live transaction, deployment or oracle push was made. The engine must be deployed, bound once on the vault and once on a fresh production venue, and the guard price pushed with `bun run price:push` before any live scenario.
- A trader contract that cannot receive cirBTC (blocklist) would block its own release; there is no admin escape by design.
